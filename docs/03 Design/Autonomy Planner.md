# Автономный алгоритм If–Then (AUTONOMY PLANNER)

Перед запуском команда настраивает поведение аппарата при потере связи.

## Форма правила
`ЕСЛИ [условие] И [доп. условие] → ТО [действие]`
Блоки перетаскиваются (на телефоне — выбираются из списков).

## Условия (сенсоры)
| Блок | Пример | Нужно оборудование |
|---|---|---|
| Signal = LOST / WEAK | `Signal = LOST` | — |
| Battery < X% | `Battery < 25%` | батарея |
| Temperature > Critical / < Freezing | | Temperature Sensor |
| Hull Integrity < X% | `Hull < 40%` | — |
| Data Buffer > X% | | Data Buffer или Data Storage |
| Sample Secured = TRUE | | Sample Container |
| Debris Detected | | Radar/Altimeter или Navigation Camera |

## Действия
| Блок | Эффект |
|---|---|
| Отключить второстепенные приборы | потребление ↓ |
| Выключить перегревающийся прибор + безопасный режим | тепло ↓, наука пауза |
| Продолжить сбор и хранить во внутренней памяти | данные копятся, память ↓ |
| Прекратить рискованные манёвры | риск корпуса ↓, прогресс ↓ |
| Перейти к подготовке возврата | фаза → возврат |
| Повернуть антенну на Землю | связь ↑ (нужна High-Gain или Omni) |
| Уклониться | топливо ↓, риск ↓ |

## Правила работы
- Число правил = ёмкость **Flight Computer** (базовый 3, улучшенный 6). Без Flight Computer — только Safe Protocol.
- Некоторые действия требуют оборудования; без него блок серый с причиной.
- **Конфликты** подсвечиваются (одно правило включает прибор, другое выключает при тех же условиях).
- Выполнение — по порядку приоритета (сверху вниз), первое совпавшее действие каждого типа побеждает.
- Перед стартом — кнопка **«Тест»**: прогон 3 сценариев (потеря связи + низкий заряд, перегрев, обломки) с выводом, какие правила сработали.
- Не настроили → **Safe Protocol**: аппарат сохраняет себя (отключает науку, ждёт связи), но может пожертвовать научными целями.

Код: `src/engine/autonomy.ts`.

## Что сделано (M2, 2026-11-14) — **проверено** (тесты + браузер)
- **Где:** вкладка «Автономия n/слоты» в конструкторе (экран 11 между сборкой и проверкой, Core Loop шаг 7) — `src/ui/AutonomyPlanner.tsx`. На проверке готовности — список правил только для чтения (`RulesSummary`).
- **Форма:** «ЕСЛИ [условие] И [доп. условие] → ТО [действие]» из выпадающих списков (как «на телефоне»; перетаскивания нет). До 2 условий, порог X% — числом (по умолчанию Battery 25, Hull 40, Buffer 90).
- **Серые блоки:** условие/действие без нужного модуля недоступно в списке с причиной «— нужен модуль: Temperature Sensor» (`blockProblem`).
- **Число правил ≤ `ruleSlots`** (Flight Computer: 3 за штуку). Без Flight Computer — сохранить нельзя, «только Safe Protocol».
- **Сохраняют** инженер или командир (`setRules`, только до проверки); остальные видят правила команды. Черновик + «Сохранить / Отменить»; чужое сохранение подтягивается, если своих правок нет. Движок проверяет то же самое (`validateRules`).
- Порядок = приоритет (↑/↓), конфликты подсвечены (`findConflicts`), кнопка **«Тест: 3 сценария»** (`testRules`: потеря связи + низкий заряд, перегрев, обломки) — какие правила сработали бы.
- **В полёте:** правила срабатывают при потере связи (`stepFlight`) и на дедлайне кризиса (`resolveCrisis`). Каждое срабатывание пишется в журнал «Сработало правило 1 «ЕСЛИ Signal = LOST → ТО Продолжить сбор…» — связи нет, аппарат действует сам» (`noteRulesFired`, `flight.rulesFired`) и в отчёт — карточка «Автономия» (`report.autonomy`: какие правила, где, сколько раз, Safe Protocol N раз).
