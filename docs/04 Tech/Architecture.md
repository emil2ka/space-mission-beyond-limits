# Архитектура

```
             ┌──────────────── клиент (браузер) ─────────────────┐
 действие →  │ UI (React)  ──dispatch──▶  Transport ──────────────┼──▶ хост
             │   ▲                          │                     │
             │   └── store (zustand) ◀── RoomState ◀─ broadcast ──┼─── хост
             │ 3D (r3f) читает store, анимирует по изменениям     │
             └────────────────────────────────────────────────────┘
 хост: reduce(state, action) из src/engine → новый RoomState → broadcast всем + сохранение
```

## Слои
| Папка | Ответственность | Зависимости |
|---|---|---|
| `src/engine/` | Чистая логика: данные, расчёты, редьюсер комнаты, симуляция полёта, правила If–Then, отчёт | никаких (только TS) |
| `src/net/` | Транспорт: `LocalTransport` (BroadcastChannel), `SupabaseTransport` | engine |
| `src/store/` | zustand: текущий RoomState, мой playerId, настройки | engine, net |
| `src/scene/` | 3D: штаб, стенд, аппарат, миссии, эффекты | store, three |
| `src/ui/` | Экраны и панели ролей | store |

## Главные правила
1. Вся логика — в `engine`, детерминированная (сид комнаты для шума). Одинаковые действия → одинаковое состояние. Это делает возможными тесты, повтор в отчёте и восстановление после переподключения.
2. UI никогда не меняет состояние напрямую — только `dispatch(action)`.
3. 3D не хранит игровое состояние, только визуальное (анимации подлёта и т.п.).
4. Числа баланса — только в `src/engine/data/`.

## Ключевые типы
`ComponentDef`, `MissionDef`, `Build` (id → count), `CraftStats`, `RoomState`, `Action`, `FlightState`, `AutonomyRule`, `CauseEvent`. См. `src/engine/types.ts`.

## Языки (RU/EN, решение 0013 §5)
- `src/i18n/`: `format.ts` (шаблоны `{x}`, множественное `{n|минута|минуты|минут}` / `{n|minute|minutes}`, вложенные сообщения), `index.ts` (стор `useLang`, `useT()`), `dict/*.ts` (фрагменты `{ ru, en }`), `data.en.ts` (английский для текстов из `src/engine/data/*`, ключ — русская строка).
- Язык свой у каждого игрока: `localStorage['sm:lang']`, по умолчанию `navigator.language` (`ru*` → ru, иначе en). Через комнату не синхронизируется. Переключатель `LangToggle` стоит на главном и в панели звука.
- **Новая строка в UI:** добавь ключ с префиксом экрана в свой фрагмент `src/i18n/dict/<область>.ts` сразу в `ru` и `en` (тип `en` требует тех же ключей), в компоненте — `const t = useT(); t('ключ', { параметры })`. Во фрагментах только данные, без импортов.
- **Текст из движка:** движок хранит русский текст (на нём тесты и логи), а рядом кладёт `i18n: { поле: Msg }`. Собирай так: `mt('ключ', p)` / `m()` / `join()` из `src/engine/msg.ts`, русский рендерится `ru(msg)` из того же словаря. В UI: `t.f(obj, 'поле')`, `t.fl(obj, 'массив')`, `t.m(msg)`.
- **Новый текст в `src/engine/data/*`:** допиши перевод в `data.en.ts`. Тест `src/i18n/__tests__/data.test.ts` упадёт, если перевода нет; `dict.test.ts` проверяет, что наборы ключей ru/en совпадают.
- Названия модулей и миссий одинаковые на обоих языках (поэтому `RTG / РИТЭГ` → `RTG`).
