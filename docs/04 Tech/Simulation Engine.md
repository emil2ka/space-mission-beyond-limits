# Движок симуляции

Всё — чистые функции в `src/engine/` (без React/three). Числа — `src/engine/data/*.ts`, таблица — [Balance Table](../03%20Design/Balance%20Table.md). Решения по модели полёта — [0010 M1 flight model](../06%20Decisions/0010%20M1%20flight%20model.md), по Астероиду и экономике — [0012 M3 asteroid and economy](../06%20Decisions/0012%20M3%20asteroid%20and%20economy.md).

## Сборка (конструктор)
- `computeStats(build, mission, mods?)` → масса, стоимость, генерация (по источникам), потребление (по потребителям), ёмкость, тепло, слоты, связь, память, проблемы. `mods` — улучшения штаба (`{ upgrades, extraSlot? }`; `room.agency` подходит как есть). Без `mods` — без улучшений.
- `canAdd(build, id, mission, mods?)` → `{ok}` или `{ok:false, reason}` с точной причиной (учитывает доп. слот).
- `readiness(build, mission, mods?)` → `{ ok, blockers, warnings, notes }` (`readiness.ts`). Блокеры: нет обязательной системы, бюджет, несовместимость, нет генерации, слоты, перегруз массы > 10 %. Предупреждения (командир может принять): дефицит, перегрузка шины, холод/замерзание, жара/перегрев, перегруз ≤ 10 % и т. п. `notes` — бесполезные модули.

## Комната (`room.ts`, `reduce(state, action)`)
Стадии: `lobby → briefing → build → review → launch → flight → report`.
| Действие | Кто | Что делает |
|---|---|---|
| `submitReview` | любой | build → review (сборка блокируется) |
| `approve` | командир | в review: блокеры → ошибка; есть предупреждения → `approve-against-warning` (`issueIds` = id предупреждений); review → launch |
| `veto {text}` | командир | в review: запись + review → build |
| `launchDone` | хост | launch → flight, `startFlight` |
| `tick` | хост | шаг полёта; в конце — `report`, `teamTrust`, `agency = recordFlight(...)` (MC начислены, повреждения записаны, `pendingPrep = true`) |
| `crisisChoice {optionId}` | роль варианта | выбор в кризисе; кризис закрывается, когда выбрали все присутствующие роли с вариантами (в демо — все роли), иначе по дедлайну |
| `scienceMode {waypoint, mode}` | учёный | `fast` / `precise` для текущей или будущей точки |
| `chooseSite {site}` | учёный | Астероид: `regolith` / `boulder` / `crack` в фазах «Сближение» и «Выбор места» |
| `unlockMission {mission}` | командир / хост | цена `unlockCost`, не во время запуска/полёта, баланс не уходит в минус |
| `buyUpgrade {id, slot?}` | командир / хост | улучшение штаба (вне проверки/запуска/полёта); `extra_slot` берёт отдел `slot` (по умолчанию «Наука») |
| `confirmPrep {insurance, next?}` | командир / хост | после полёта: списывает `prepCosts(...)` (или бесплатный базовый ремонт + стартовая сборка), report → `next` (`build` по умолчанию / `lobby`) |
| `loadAgency {agency}` | хост, лобби | восстановить штаб из `exportAgency` (строка или объект, всё чистится) |
- `decisions` сбрасываются при изменении сборки (нужно новое утверждение), `decisionLog` — вся история попытки (для отчёта).
- `goStage` оставлен для совместимости со старым UI (`goStage flight` тоже стартует полёт). **Уход из отчёта (`goStage build`/`lobby`) тоже идёт через подготовку** — без страховки, по цене `report.mc.upkeep`, которую отчёт показал заранее.
- `room.agency` — источник правды для MC/разблокировок; `room.credits` и `room.unlocked` — зеркала для экранов M1/M2 (обновляются каждым действием). Комната без `agency` (сохранена до M3) восстанавливает его из старых полей.
- `statsOf(room)` = `computeStats(build, mission, agency)`.

## Полёт (`flight.ts`, `crises.ts`, `sim.ts`)
`startFlight(mission, build, {teamTrust?, mods?})`, `stepFlight(flight, build, seed, rules = [])` — один тик (1 тик = 1 с реального времени, 10 игровых минут).

Порядок тика:
1. **Буря** (источник Signal Distortion) — момент из сида, без Signal Amplifier всегда.
2. **Нет связи?** (вход: первые 15 тиков; эскалация бури; нет канала) → правила Autonomy Planner, если ни одно не подошло — **Safe Protocol** (аппарат зависает, наука выключена).
3. **Что включено:** роторы — в полёте и при зависании (быстрый режим), при посадке (точный режим) выключены; приборы науки — во «Входе» и «Полёте по точкам».
4. **Энергия:** `stepEnergy` (заряд, отключение по приоритетам; без PDU — самый мощный первым).
5. **Защита шины:** после Power Drop перегруженная шина отключает потребителей сразу.
6. **Тепло** работающих узлов − потери среды × (1 − изоляция); пороги: ≤ −80 замерзание, ≥ 120 жарко, ≥ 200 перегрев.
7. **Маршрут:** дюны → озеро → кратер, 70 тиков перелёта на точку (× скорость), стоянка 20 (быстрый) / 40 (точный).
8. **Наука → память → связь:** 4 цели Титана (`TARGET_DEFS`), память 20 + Data Storage/Buffer, при переполнении данные теряются (`queueFull`), передача `bandwidth × 1/6` ед./тик, в бурю медленнее и с потерями.
9. **Кризисы:** не раньше 10-го тика, по одному, пауза 25 тиков, не больше 3 за полёт, каждый вид один раз. Таймер 20 тиков.
10. **Фазы:** Перелёт 30 → Вход 60 → Полёт по точкам до 360 (кончается раньше, если все точки пройдены) → Передача данных 120. Итого **480–570 тиков = 8–9.5 минут**.

### Кризисы (детерминированы от сборки, [0006 Deterministic crises](../06%20Decisions/0006%20Deterministic%20crises.md))
| Кризис | Триггер | Чем лечится |
|---|---|---|
| Power Drop (bus) | нагрузка > предела шин | снять ватты (наука, узел, экономная связь); иначе защита шины отключит потребителей |
| Power Drop (battery) | дефицит и заряд < 20 % | снять дефицит или подзарядиться; иначе батареи сядут |
| Overheat | ≥ 200 три тика / ≥ 120 шестьдесят тиков | посадка/охлаждение, выключить горячий прибор, пауза; иначе корпус −10 и отказ прибора |
| Freeze | ≤ −80 три тика | Heater / тепло RTG; учёный может усыпить приборы; иначе отказ прибора |
| Signal Distortion | буря (без Signal Amplifier всегда) | связь перенастраивает/наводит антенну; без ответа — потеря связи на 20 тиков |
Без выбора к дедлайну: подходящее правило Autonomy Planner (`by: 'autonomy'`), иначе Safe Protocol (`by: 'safe'`). Всё пишется в `causes` с `causeIds` (id компонентов и id предупреждений проверки), итог — в `history`.

## Полёт Астероида (`asteroid.ts`, `data/asteroid.ts`) — M3
Тот же `FlightState` + `flight.asteroid: AsteroidFlight` (только на Астероиде). Общие механики Титана работают как есть: энергия, шина, тепло, данные → память → связь, blackout + Autonomy Planner / Safe Protocol, радио и команды, Power Drop / Overheat / Freeze.

Фазы (`missions.ts`, тики — максимумы): **Перелёт ≤ 140** (Ion Engine 140 тиков / химия 100, кончается по прибытии) → **Сближение ≤ 120** (80 тиков с Navigation Camera / Radar, 110 без; кончается при `approach = 1`) → **Выбор места 40** → **Отбор 100** (раньше, если сработало правило «Sample Secured → подготовка возврата») → **Упаковка 30** → **Обратный перелёт и возвращение 190** (импульс 10 тиков, перелёт до 130-го, капсула: отделение 130 → вход 140 → парашют 155 → посадка 170 → найдена 173 с маяком / 185 без маяка при посадке в расчётной точке / не найдена при уходе от точки). Итого **541–590 тиков ≈ 9–10 минут** (до ~620 при медленном сближении).

- **Что включено** (`asteroidActivity`): химия — сближение, выбор места, отбор, импульс (и перелёт, если нет Ion Engine); Ion Engine (60 W) — перелёты; рука/бур — только во время отбора; Sample Sealing Unit — в упаковке; маяк — в возвращении; приборы — сближение…упаковка. Rotor System здесь никогда не включается и не двигает аппарат.
- **Топливо:** `fuelMax = 100 × Propellant Tank`. Перелёт: ион 0.07/тик, химия 0.4/тик; сближение 0.3/тик; удержание у поверхности 0.05/тик; импульс домой: химия 30, с ионом 5 + 0.07/тик. Перегруз ×(1 + 3 × доля перегруза). Не хватило на импульс → капсула садится далеко (`offTarget`). Ion Engine отключился (энергия) → перелёт продолжается на химии (`ion-lost`).
- **Отбор:** инструмент = рука, бур или оба (скорость по месту, `SITE_DEFS`); `sampling: idle → reach (12 тиков) → grab → stowed / jam / failed`; к концу фазы ≥ 40 % → берётся меньший образец, меньше — образца нет. Сближение не завершилось → отбора нет.
- **Герметизация:** 20 тиков Sample Sealing Unit в упаковке; без него / отключён → `not-sealed`.
- `chooseSite(flight, site)`; без выбора к концу фазы — компьютер берёт реголит (`siteBy: 'auto'`).
- Повреждённый обломками Heat Shield → на входе образец перегревается (`heated`).
- Blackout на Астероиде: после уклонения без Star Tracker / Reaction Wheels антенна теряет Землю на 8 тиков (если связь не рассчитала наведение заранее).

### Кризисы Астероида
| Кризис | Триггер (сборка + сид) | Роли | Без ответа |
|---|---|---|---|
| Debris Alert | сближение, тик 15–45 из сида; без Micrometeoroid Shield — всегда, с ним — 25 % сидов. Без Radar / Navigation Camera таймер 8 с вместо 20 (`variant: 'late'`) | командир: уклониться (−12 топлива, +8 тиков) / продолжить; инженер: щитом к потоку (урон /3) или укрыть капсулу (Heat Shield цел, корпус −4); связь: заранее рассчитать наведение | правило `debris_detected → evade` / `stop_risky_maneuvers`, иначе Safe Protocol: замереть (урон ×0.5, без щита и укрытия — Heat Shield повреждён) |
| Sampling Arm Jam | отбор, при наборе 20–50 % (сид); риск = место (реголит 0.35 / камень 0.8 / трещина 0.6) − 0.6 с Vibration Dampers или +0.3 без (+0.1 с буром без гасителей, +1 если рука погнута обломками) | инженер: перезапуск / изоляция привода; командир: повторить в соседней точке / забрать что есть; учёный: на бур / снимок заклинивания (перезапуск без потери скорости); связь: состав первым | правило `prepare_return` (забрать что есть) / `stop_risky_maneuvers`; Safe Protocol — привод стоит 25 тиков, потом половинная скорость |
Debris и Jam всегда получают свою очередь (ждут, пока идёт другой кризис); общих кризисов (Power Drop / Overheat / Freeze) на Астероиде — не больше 2.

### Панели ролей
`panelFor(role, flight, build): RolePanel` (`panels.ts`) — общие `items/alerts/hidden/crisis` + своё: `power` (инженер), `science` (учёный, с выбором режима), `comms` (связь), `command` (командир: таймер, корпус, статус; без технических причин и без узлов).
На Астероиде ещё `panel.asteroid: AsteroidPanel`: инженер — `fuel` (сейчас / максимум / прогноз «нужно ещё ≈N»), `engines`, `protection` (щит, Heat Shield, рука); учёный — `site` (3 места с риском заклинивания **для этой сборки**, `canChoose`), `arm`, `sample`, `composition`; связь — `composition`, `capsule`; командир — `fuel`, `sample`, `capsule` + общий статус/корпус/таймер. Всегда `approach`, `debris`, `phaseId` (для 3D).

## Отчёт (`report.ts`)
`buildReport(room): MissionReport` — исход, баллы по 7 весам из [Mission Report](../03%20Design/Mission%20Report.md) (`scoreWeightsFor(mission)`), цепочки причин (главные 3 первыми), решения командира, Team Trust и причины изменения, вклад ролей, MC, моменты для 3D-повтора, `damaged` (что чинить). Вызывается в `tick` в конце полёта и кладётся в `room.report`.
- Астероид: веса — главная задача 35 (0.6 образец на Земле + 0.4 доставка данных состава), данные 20, аппарат 10, связь 15, **сохранность образца 10** (герметичен 1 / нет 0.5 × масса/40 г × 0.5 при перегреве), **возвращение 5** (найдена 1 / не найдена 0.3), ресурсы 5 (½ бюджет + ½ остаток топлива ≥ 10 %). **Perfect только если образец герметичен, капсула найдена и данные состава доставлены**, иначе максимум Success; образца на Земле нет — максимум Partial. `report.asteroid` — место, образец, капсула, топливо, флаги Perfect. Цепочки: `debris_alert`, `arm_jam`, `no-sample`, `sample-small`, `not-sealed`, `heat-shield`, `capsule-lost`, `fuel`, `ion-lost`, `site-auto`, `composition` + общие.
- `mc = { earned, upkeep, total, balance, prep }`: `upkeep` = сколько возьмёт следующая подготовка (0 при бесплатном ремонте), `prep` — её строки.

## Экономика (`economy.ts`, `data/economy.ts`) — M3, тест E
```ts
interface Agency { credits; unlocked; upgrades; damaged; history; extraSlot; hullLoss; insured; coveredRepairs; pendingPrep; basicRepairs; lastPrep }
newAgency(); missionReward(outcome, delivered); recordFlight(agency, {mission, outcome, earned, broken, hull})
prepCosts(agency, insurance): PrepCosts   // { items, total, affordable, fallback, charge, balanceAfter, missing } — показывается ДО подтверждения
applyPrep(agency, insurance)              // списывает total; не хватает даже без страховки → free_basic_repair (0 MC, damaged очищены)
unlockMission(agency, mission); buyUpgrade(agency, id, slot?)
exportAgency(agency): string; importAgency(unknown): Agency | null
```
- После полёта `pendingPrep = true`: «Ещё раз» / «В штаб» обязательно проходят подготовку (`confirmPrep` или `goStage` из отчёта). Подготовка: обслуживание 10 + диагностика 5 + ремонт модулей (по 20 % цены модуля, не меньше 5) + корпус (2 MC за 10 %) + расходники 5 + страховка 15 (по желанию: ремонт после **следующего** полёта бесплатный).
- Не хватает на подготовку → **бесплатный базовый ремонт**: баланс не трогается, аппарат = `STARTER_BUILD[mission]` (проходит проверку готовности). Тратить MC на разблокировку/улучшения до подготовки можно — подстраховка та же. Баланс никогда не меньше 0, soft-lock невозможен (проверено случайными последовательностями).
- Улучшения (`UPGRADES`, 50–80 MC) меняют `computeStats` и полёт (через `flight.mods`): лёгкие сплавы (корпус −10 % массы; урон обломков ×1.25), антенны (+30 % канала; +20 % энергии), батареи (+25 % ёмкости; +3 кг каждая), PDU v2 (`smartShed`: отключённое при разряде включается обратно, когда заряд > 50 %; PDU 8 W вместо 5), доп. слот (+1 слот отдела; +5 кг корпусу), Flight Computer v2 (6 правил; +5 W, +3 тепла).
